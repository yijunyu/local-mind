随数字而来的注意事项

⛔ 已撤回：此前此处写"重复提示（KV 复用）我们胜 1.3–2.1×"。该分支并不存在：本引擎的 CUDA 路径没有实现跨请求前缀复用，服务端启动时即如此声明，而且日志里"可复用 100%"的提示被整段重新预填充。具备前缀匹配的是 ds4.c，所以这条轴上的优势属于对方。此外原文那组数字也过不了单位核算——1584 上下文下 128 个生成 token 仅凭解码就需 ≥6.29 s，不可能总耗时 4.27 s。

"提示重复率无法测量"同样不成立：逐请求的前缀复用率一直默认开启记录。一次真实 claude -p --continue 会话实测为 98.4% / 83.5% / 77.8%（2026-07），并由 llama.cpp 自身的槽位缓存独立复核到几个 token 之内。

领先依赖开关：2.32× 整段提示修复与上面的端到端领先都来自默认关闭的配置；解码 +10% 已上线且逐位稳定。是否上线，是速度与可复现性的取舍。

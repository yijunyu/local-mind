Caveats that travel with the number

⛔ Retracted: this line used to read "repeated prompts (KV reuse): we win 1.3–2.1×". That branch does not exist. Our CUDA path implements no cross-request prefix reuse — the server says so at load, and a prompt its own log reports as 100% reusable is re-prefilled in full. ds4.c is the engine with prefix matching, so the advantage on that axis is its own. The old figures also fail a units check: at 1584 context, 128 generated tokens cost ≥6.29 s in decode alone, so a 4.27 s total is not possible.

"The hit rate cannot be measured" was also wrong: per-request prefix reuse is logged by default. A real claude -p --continue session measured 98.4% / 83.5% / 77.8% (2026-07), independently confirmed to within a few tokens by llama.cpp's own slot cache.

The lead is flag-gated: both the 2.32× whole-prompt fix and the end-to-end lead above come from a default-off configuration. Decode +10% is shipped and bit-stable. Shipping it is a speed-versus-reproducibility trade.
